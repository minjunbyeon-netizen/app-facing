## 1. P0 — 론칭 전 반드시 (실사용자를 받는 순간 문제가 되는 것)

### P0-1. 이용약관 본문 부재 ★최우선
- **실측**: 앱 가입 화면의 "이용약관" 링크를 누르면 본문이 `"이용약관 본문은 정식 출시 시 업데이트됩니다."` 1줄 (signup_screen.dart:255)
- **왜 P0**: 결제(회원권)·전자계약을 다루는 서비스가 약관 없이 가입을 받으면 분쟁 시 방어 근거가 없음. 스토어 심사에서도 반려 사유
- **할 일**: 표준 약관 골격(서비스 정의 / 계정·가입 / 박스-회원-FACING 3자 관계 / 전자계약 효력 / 결제·환불은 박스 책임 명시 / 면책 / 분쟁 관할) 초안 작성 → 본문 화면 신설(개인정보 화면과 같은 패턴)
- **분량**: 초안 작성 2h (Claude 가 초안 → 사용자 검토). 법무 검토는 출시 후라도 베타 고지로 커버 가능

### P0-2. 계정 탈퇴가 로컬만 지움 (서버 데이터 잔존)
- **실측**: privacy_screen.dart:131 — `TODO: 실제 서버 DELETE /api/v1/profile 호출은 Phase 2`. 현재 탈퇴 버튼은 prefs.clear() 만
- **왜 P0**: 방침 화면에 "탈퇴 = 서버·로컬 모든 데이터 영구 삭제"라고 **이미 약속**해 놓고 실제로는 서버에 남음 — 고지 내용과 동작 불일치는 개인정보보호법 리스크
- **할 일**: 둘 중 하나. (a) 백엔드 DELETE endpoint 1개 + 앱 호출 1줄 (반나절) ← 권장 / (b) 방침 문구를 "탈퇴 요청 시 카카오톡 상담으로 접수, N일 내 삭제" 로 현실에 맞게 수정 (10분)

### P0-3. 고객지원 체계 공백 (특히 사장 쪽 0개)
- **실측**: 앱 = Profile 의 카카오톡 상담 버튼 1개. **웹 어드민 = 전 페이지에 문의 진입점 없음** (footer 는 "v0.4 · Phase 2 (베타)" + 로그아웃뿐)
- **왜 P0**: 돈 내는 쪽(사장)이 막혔을 때 갈 곳이 없음. 초기 박스 1~2곳 운영 단계에서 이탈 직결
- **할 일**: ① 웹 어드민 footer/사이드바에 "문의하기" (카톡 채널 동일 링크 + 메일) ② 앱 Profile 버튼 라벨을 "고객센터 (카카오톡)" 로 명확화 ③ 응답 가능 시간 1줄 ("평일 10-18시 답변")
- **분량**: 1h

### P0-4. 화면에 노출되는 "현재 mock" 문구
- **실측**: algorithm_screen.dart:68 — Tier 산정 설명에 `"(Phase 2 확정 — 현재 mock)"` 이 회원에게 그대로 노출. 백분위·랭킹 가상 데이터 고지도 방침에서 금일 삭제됐는데 algorithm 화면과 정합 재확인 필요

## 2. P1 — 론칭 주간 내 (첫 박스 온보딩 전에)

### P1-1. 사장용 "시작 가이드" 보강 — 계약 발송 흐름
- **현재**: /onboarding 3단계 위저드는 잘 만들어짐 (회원 등록 → 코치·운영 → 자동화). 그러나 **전자계약 발송**은 "QR 로 서명하고 PDF 자동 저장" 1줄뿐
- **부족한 것**: 사장이 실제로 묻게 될 순서 — "템플릿은 어디서 만들지? → 변수는 뭘 채우지? → 회원 폰에 어떻게 뜨지? → 서명 후 PDF 는 어디서 받지?"
- **할 일**: /contracts 첫 진입 시(계약 0건) 빈상태를 5단계 안내로 확장: `① 템플릿 작성 → ② 계약서 발급(회원+변수) → ③ 발송 → ④ 회원 앱 Profile→Contracts 에서 서명 → ⑤ PDF 다운로드`. 현재 빈상태는 "계약서 없음. + 계약서 발급 으로 작성하세요." 1줄
- **분량**: 1.5h

### P1-2. 회원권 플랜 템플릿 예시

### P1-4. 코치 페어링 코드 유효시간 명시

### P1-5. 박스 가입 "거절" 시 회원 안내 부재

### 자기반박 3건 (§0-C-3)
1. **P0-2 를 P0 로 둔 것은 보수적 판정** — 베타 기간 + 사용자 소수면 (b)문구 수정으로 강등 가능. 다만 방침-동작 불일치는 기간과 무관하게 남으므로 P0 유지가 안전
2. **P1-6 스토어 패키지는 배포 방식 결정에 종속** — APK 직배포(MVP 계획)면 P2. Play Store 등록 결정 시에만 P1
3. **웹 어드민 조사 중 classes/coaches/care/lockers/stats 일부는 파일 앞부분(50~150줄)만 정밀 확인** — 뒷부분에 추가 placeholder 가 있을 가능성 잔존. 단 전 페이지 라우트·빈상태·네비는 전수 커버함
