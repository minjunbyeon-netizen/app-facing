## 1. i18n 우선순위·확장 (EN·JA·ZH)

### 1.1 우선순위 근거

**EN 먼저 — 근거 3가지**:

1. **p6(David Choi) task_complete 0%** (report §C3 이슈 #4). "I cant use my own admin tool because everything is in Korean." — 단일 페르소나 6건 집중 + 도메인 weight 1.5. EN만 추가해도 이 블로커 해소.

2. **한국 CrossFit 박스 외국인 코치·사장 분포**: PHASE3_ROADMAP §5.1 "한국 CrossFit 박스 30%+ 가 외국인 코치·재한 외국인 회원 보유" 추정. CrossFit 특성상 영어권 코치(미국·호주·캐나다) 채용 일반화. EN은 사실상 이미 de-facto 요구사항.

3. **ux-testing.md §7 Demographic 마찰 표**: "디지털 초보" 패턴 중 "전화 선호, 링크 탐색" — 외국인 사장은 한국어 UI를 "초보 경험"으로 체험. 언어 장벽이 디지털 리터러시 장벽과 중첩 → 이탈 확률 극히 높음.

### 1.2 JA·ZH 확장 시점

| 언어 | 확장 트리거 | 근거 |
|---|---|---|
| **JA (일본어)** | 일본인 CrossFit 사장/코치 박스 5곳 이상 문의 확인 시 | 한국 CrossFit 일본인 코치 존재하나 EN 대비 소수. Phase 4 (1,000박스) 진입 전. |
| **ZH (중국어)** | 중국계 사장 박스 5곳 이상 + 요구 확인 시 | 재한 중국 커뮤니티 CrossFit 박스 소수. Phase 4 이후. |
| **JA·ZH 공통 전제** | Flask-Babel locale 파일 구조 확립 후 | N3-1 완료 시 locale JSON 파일 추가만으로 확장 가능하게 설계 필수. |

**결론**: EN only for N3. JA·ZH는 Phase 4 트리거 조건 달성 후 진행.

### 1.3 i18n 기술 구현 주의사항

- **Flask-Babel + Babel Extract**: gettext `_()` 래핑 → `.pot` → `.po` → `.mo` 컴파일. JSON locale 파일은 프론트엔드 JS 전용 (토스트·동적 메시지).
- **날짜·통화 locale** (N3-5): `babel.dates.format_date(locale='en_US')` / `₩50,000` → `KRW 50,000` 또는 `₩50,000` (EN에서도 한국 원화 표기 유지, 환산 금지).
- **RTL 대응 불필요**: EN·JA·ZH 모두 LTR. CSS 방향 전환 없음.
- **브라우저 자동번역 보완 (빠른 우회)**: report p6 권장 사항 — `<html lang="ko">` → `<html lang="ko">` 유지 + EN 선택 시 `lang="en"` 으로 동적 교체. Chrome 자동번역 트리거 방지 (이중 번역 방지).

## 2. 영문 계약·영수증 법무 검증 권고

### 2.1 법무 검증 필요 범위

**한국법 적용 원칙**: 한국 내 CrossFit 박스 계약은 외국인 회원 대상이라도 **한국 소비자보호법(공정거래위원회 표준약관)** 적용. 영문 번역만으로는 법적 효력 충분하지 않을 수 있음.

| 항목 | 법무 필수 여부 | 근거 |
|---|---|---|
| **환불 규정 (학원비 환불 준용)** | ✅ 필수 | 공정거래위원회 「체육시설업 표준약관」 강행규정. 영문 번역이 한국 법령과 상충 시 한국 법령 우선. |
| **개인정보 처리 동의 (PIPA)** | ✅ 필수 | 개인정보보호법(PIPA) 영문 동의서도 동일 요건. 수집 항목·목적·보유기간 명시 의무. |
| **서명 효력** | ✅ 필수 | 전자서명법 — 전자계약서 법적 효력 요건 확인 필요. 외국인 회원의 디지털 서명 + 이메일 확인 조합 권장. |
| **기간·금액 표기** | 권장 | 영문 표기 시 KRW 단위 명확히. 환율 기준일 미기재 시 분쟁 소지. |
| **분쟁 관할 법원** | 권장 | "한국 법원 관할" 영문 명시 권장. |

### 2.2 권고 접근 (영문 번역 vs 법무 자문)

**1단계 (N3 범위)**: 영문 번역 + 법률 면책 문구 추가.
```
"This document is an English translation for reference only.
In the event of any discrepancy between the Korean and English versions,
the Korean version shall prevail."
```

**2단계 (30박스 이상, N6-3 이후)**: 체육시설업 전문 변호사 1회 자문 (추정 50~100만원). 표준 EN 계약서 템플릿 1개 확정. 이후 반복 사용.

**판단 기록**: 법무 자문을 N3에서 강제하지 않고 N6-3(30박스) 이전으로 지연. 이유: N3은 EN UI 자립이 핵심, 법무 자문은 사업 규모 리스크가 커지는 30박스 시점이 ROI 적합. 반대 시 수정 범위: N3-3 task에 "법무 자문 완료 후 배포" 조건 추가.

### 2.3 세금계산서 영문 표기

**한국 국세청 규정**:
- 세금계산서는 **한글 강제** (부가가치세법 시행규칙 제53조 — 사업자 등록번호, 공급가액, 세액 등 법정 기재사항은 한국어).
- 영문 표기 가능 항목: 품목명(한글+영문 병기), 사업장 주소(영문 병기), 거래처명(영문).
- 불가 항목: 공급가액 단위(반드시 "원"), 세금계산서 명칭("Tax Invoice" 병기는 가능하나 한글 "세금계산서" 필수).

**실무 해결책 (2 버전 분리)**:
| 버전 | 용도 | 내용 |
|---|---|---|
| **한글 세금계산서** | 사장 세무사 제출, 국세청 신고 | 법정 양식 그대로 |
| **영문 영수증 (Receipt)** | 외국인 회원 경비 처리용 | "Receipt" 양식 별도 — 세금계산서 아님, 단순 영수증. 품목·금액·VAT 영문 표기. |

**구현**: N3-4 task를 "영문 영수증 (Receipt) PDF 생성"으로 명칭 변경. 세금계산서 영문화가 아님을 명확히.

## 3. onboarding 컨텐츠 한국어 타이포·시각 위계 적용

### 3.1 N6-2 "영상 튜토리얼 10분 + PDF 50~100p" 재검토

**cardnews-quality §2 시각 위계 기준 적용**:

| 컨텐츠 형식 | 원안 | 재검토 결과 |
|---|---|---|
| 영상 튜토리얼 | 10분 onboarding + 30분 상세 | **유지** — 10분은 TTFV 목표(8분 이내 activation)에 근접. 30분 상세는 고급 기능용. |
| PDF 매뉴얼 | 50~100p | **축소 권고 40p 이하** — ux-testing §6.1 SaaS 온보딩: 84% 첫 세션 포기율, empty state guidance 필요. 100p PDF는 첫 세션 인지 부하 과다. "빠른 시작 가이드 8p + 전체 레퍼런스 40p" 분리. |
| FAQ + 도움말 센터 | 단순 언급 | **우선순위 상향** — Nielsen H10. report C4에서 도움말 0개가 31건 마찰의 주요 원인. |

### 3.2 타이포·시각 위계 가이드라인 (cardnews-quality §2·§3 적용)

**영상 튜토리얼 (화면 캡처 기반)**:
- 화면 강조 텍스트: **Pretendard Variable w700, 18~20px** (모바일 가독성 기준)
- 자막/설명: 16px w400, line-height 1.6, letter-spacing -0.02em
- 강조 라벨 (버튼·메뉴 위치 지시): 14px w500 + accent 색 테두리 박스

**PDF "빠른 시작 가이드" (8p)**:
- 폰트: Pretendard Variable (OFL 무료, 한·영 일관성 ★★★★★)
- 폰트 위계 4단계:
  - H1 (페이지 제목): 28~36px w700
  - H2 (단계 헤더): 20~24px w600
  - 본문: 16~18px w400, line-height 1.6
  - 캡션/주석: 13~14px w500
- 색상: 60% 흰 배경 + 30% 중성 (#F5F5F5 섹션 배경) + 10% accent (CrossFit red #EE2B2B 강조)
- 이미지: 화면 스크린샷 + 빨간 화살표 오버레이 (캡처 도구: ShareX 또는 Loom)

**PDF "전체 레퍼런스" (40p)**:
- 본문 폰트 최소 16px (노안 사장 p9·p10 대비 — ux-testing §7.3 45-64세 "작은 텍스트·버튼: Medium 도전")
- 섹션 인덱스 + TOC 필수 (H10 — 찾기 쉽게)

### 3.3 RITE 방법 onboarding 검증 적용

**ux-testing §3 RITE (Rapid Iterative Testing and Evaluation)**:
- 30박스 onboarding 시작 전 → 5명 파일럿 박스 사장에게 영상+PDF 테스트
- 문제 발견 즉시 수정 → 다음 5명에게 변경본 테스트
- 2라운드 × 5명 = 10명으로 85%+ 이슈 발견 가능 (Nielsen 5-user rule)
- 팀 전원 관찰 참여 (나 혼자 보지 말고 코치·매니저 함께)

## 5. 셀프 onboarding 자동화 vs 30분 세션 hybrid

### 5.1 현황 분석

**N6-3·N6-4 원안**: "박스마다 30분 onboarding 세션" → 30박스 = 30회 × 30분 = 15시간. 100박스 = 50시간. 1인 운영 시 **스케일 불가**.

**ux-testing §6.1 SaaS 온보딩 데이터**:
- TTFV 업계 중위: 36시간 / 상위 제품: 8분 이내 activation
- 40-60% 신규 SaaS 사용자가 첫 주에 이탈 (Mixpanel 2023)
- Empty state + contextual guidance → task completion 30-45% 개선 (NN/g)
- "단일 명확한 첫 행동" 제시가 Day 1 engagement 핵심

**결론**: 30분 세션만으로는 100박스 불가. 셀프 onboarding이 1차, 30분 세션은 보완.

### 5.2 Hybrid 모델 (권장)

```
[레벨 1 — 셀프 onboarding (자동화)]
  - 첫 로그인 → 3단계 setup wizard (ux-testing §6.1 Setup wizard 패턴)
    Step 1: 회원권 상품 1개 설정 (5분)
    Step 2: 첫 회원 1명 추가 (3분)
    Step 3: 계약서 1건 발행 (2분)
  - 각 단계 완료 시 토스트 + 다음 단계 CTA (H6: Recognition)
  - 8분 이내 TTFV 달성 목표

[레벨 2 — 영상 튜토리얼 (자율)]
  - 10분 핵심 기능 영상 + 30분 상세 영상 (YouTube unlisted)
  - 빠른 시작 가이드 8p PDF

[레벨 3 — 30분 그룹 세션 (확장성)]
  - 개별 세션 → 주 1회 그룹 Zoom 세션 (5~10박스 동시)
  - 5박스 → 30박스: 개별 선택 (주 2회 그룹 세션)
  - 30박스 → 100박스: 그룹 전용 (개별 세션 제공 안 함)
  - 세션 녹화 → 도움말 센터 업로드 (지식 누적)

[레벨 4 — CS 채널]
  - 카카오 상담 + FAQ (N6-5)
```

**100박스 시 시간 비용 추산**:
- 레벨 1(셀프): 시간 0 (자동)
- 레벨 2(영상): 제작 40시간 1회 → 반복 0
- 레벨 3(그룹 Zoom): 주 2회 × 1시간 × 4개월 = 32시간 (100박스 달성)
- 합계: 초기 40시간 + 운영 32시간 = 72시간 (vs 원안 50시간 개별 세션 + 반복 불가)

## 6. NPS·CS·CS 자동화 plan

### 6.1 NPS 측정 — 한국 시장 기준

**ux-testing.md에 NPS 직접 데이터 없음** — 단, Nielsen H1(시스템 상태 가시성)과 연계: NPS는 시스템 상태에 대한 사용자 인식의 집계.

**한국 SaaS NPS 벤치마크 (외부 참조)**:
- B2B SaaS 글로벌 중위: NPS 32~45 (Qualtrics 2024 XM Institute)
- 한국 IT 서비스 NPS: 30~50 범위 (로컬 SaaS 제한 데이터)
- CrossFit 도메인 특성: 충성도 높은 커뮤니티 → 만족 시 NPS 60+ 달성 가능 (PHASE3_ROADMAP 목표 현실적)

**NPS 측정 방법**:
| 항목 | 내용 |
|---|---|
| 측정 주기 | 분기 1회 (원안 유지) + 박스 첫 가입 후 30일 시점 자동 트리거 (첫 인상 포착) |
| 측정 채널 | 이메일 설문 (박스 사장 대상) + 앱 내 팝업 (부차적) |
| 설문 도구 | Typeform 또는 Google Forms (초기), 100박스 이후 Delighted 또는 Survicate 검토 |
| 최소 신뢰성 | n ≥ 20 박스 이상일 때 유의미. 5~30박스 구간은 정성 인터뷰 병행 |
| 추적 지표 | NPS 점수 + Promoter 코멘트(기능 강점) + Detractor 코멘트(이탈 신호) |

### 6.2 CS 응답 체계 — 100박스 스케일링

**현황 우려**: N6-5 원안 "≤4시간 영업일 응답". 100박스 × 평균 50명 회원 = 5000명. 사장+직원이 문의 주체 → 100박스 기준 일 5~20건 예상.

**단계별 CS 자동화**:

| 단계 | 박스 수 | CS 방식 | 예상 일 문의 |
|---|---|---|---|
| **Phase 3 초기** | 5~30박스 | 카카오 채널 직접 응답 | 1~5건/일 |
